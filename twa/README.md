# Android wrapper (TWA)

This folder builds the **Super Cards Android app**. It is a
[Trusted Web Activity](https://developer.chrome.com/docs/android/trusted-web-activity/) —
a thin native shell that opens `https://super-cards.onrender.com` full-screen in Chrome,
with no browser UI.

**There is no app logic here.** The APK contains no HTML, CSS, JS, or Python — it points at
the live site. Deploying the server updates the app instantly; you only rebuild the APK to
change the icon, name, colours, or version.

---

## What is committed vs. generated

| Path | Committed? | Notes |
|---|---|---|
| `twa-manifest.json` | ✅ **yes** | Source of truth — edit this, never the generated files |
| `README.md` | ✅ yes | This file |
| `app/`, `gradle/`, `gradlew*`, `*.gradle`, `store_icon.png` | ❌ no | Regenerated by `bubblewrap update` |
| `*.apk`, `*.aab` | ❌ no | Build output |

Everything generated is in `.gitignore`. To recreate it on a fresh clone, run
`bubblewrap update` (step 3 below).

## Prerequisites (already installed on this machine)

| Tool | Location |
|---|---|
| Node + Bubblewrap CLI | via `nvm` — `~/.nvm` |
| JDK 17 (Temurin) | `~/android-toolchain/jdk17` |
| Android SDK | `~/android-toolchain/sdk` |
| Signing keystore | `~/android-toolchain/keys/super-cards.keystore` |

Bubblewrap's paths live in `~/.bubblewrap/config.json`. Verify with `bubblewrap doctor`.

> **Note:** the Android SDK needs `sdkmanager` reachable at `<sdk>/bin`, so
> `~/android-toolchain/sdk/bin` is a symlink to `cmdline-tools/latest/bin`. Bubblewrap's
> path validation fails without it.
>
> Bubblewrap also pins **build-tools 36.1.0** specifically — installing a different version
> is not enough.

## Rebuilding the APK

Every shell needs nvm loaded first:

```bash
export NVM_DIR="$HOME/.nvm" && . "$NVM_DIR/nvm.sh"
```

Then, from this folder:

```bash
cd twa && bubblewrap update && bubblewrap build --skipPwaValidation
```

The build asks for the keystore password twice. To avoid the prompts:

```bash
export BUBBLEWRAP_KEYSTORE_PASSWORD="$(grep '^password: ' ~/android-toolchain/keys/super-cards.keystore.password.txt | cut -d' ' -f2)" && export BUBBLEWRAP_KEY_PASSWORD="$BUBBLEWRAP_KEYSTORE_PASSWORD"
```

Outputs:
- `app-release-signed.apk` — sideload this (share the file, tap to install)
- `app-release-bundle.aab` — Play Store format, only needed if you ever publish

`--skipPwaValidation` skips a Lighthouse run against the live site. Drop it if you want
Bubblewrap to check the PWA quality criteria — but note it will be slow, or fail outright,
whenever the Render free instance is cold.

## Shipping a new version

Bump **both** fields in `twa-manifest.json` — Android rejects an update whose
`appVersionCode` did not increase:

```json
"appVersion": "1.1.0",
"appVersionCode": 2
```

Then rebuild. Reinstalling over an existing install requires the **same signing key**.

---

## The signing key — read this

`~/android-toolchain/keys/super-cards.keystore` (password in
`super-cards.keystore.password.txt` beside it).

- **Back both files up somewhere safe, off this machine.**
- It lives outside the repo on purpose and is gitignored — never commit it.
- Lose it and you cannot ship an update that installs over the current app; users would
  have to uninstall first.
- Before any Play Store release, consider generating a fresh key — and note that Google
  re-signs uploads with its own key, so the fingerprint in `config.py` would need updating
  to Play's.

## How the URL bar gets hidden

Chrome only drops its address bar if the site vouches for the app. That happens via
**Digital Asset Links**: `/.well-known/assetlinks.json` on the production domain must list
the app's package name and signing fingerprint.

That route is served by Flask — see `assetlinks()` in `app.py`, driven by
`TWA_PACKAGE_NAME` and `TWA_SHA256_FINGERPRINT` in `config.py`. Both are committed
defaults; neither is a secret.

**The values must match `twa-manifest.json` and the keystore.** If they drift, the app
still works but shows a Chrome URL bar at the top.

Re-print the fingerprint after a key change:

```bash
~/android-toolchain/jdk17/bin/keytool -list -v -keystore ~/android-toolchain/keys/super-cards.keystore -alias super-cards | grep SHA256:
```

Verify it is live in production:

```bash
curl -s https://super-cards.onrender.com/.well-known/assetlinks.json
```

> The assetlinks route must be **deployed to production before** the app is installed —
> Chrome caches the verification result at install time.
